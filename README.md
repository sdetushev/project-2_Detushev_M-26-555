# Примитивная база данных

Консольное приложение на Python для создания таблиц и управления записями. Поддерживает основные CRUD-операции: добавление, просмотр, изменение и удаление данных, а также сохранение таблиц между запусками.

## Требования и установка

Для работы необходимы Python 3.12 или новее и менеджер пакетов [`uv`](https://docs.astral.sh/uv/).

Клонируйте репозиторий:

```bash
git clone git@github.com:sdetushev/project-2_Detushev_M-26-555.git
cd project-2_Detushev_M-26-555
```

Установите зависимости:

```bash
make install
```

Запустите приложение:

```bash
make run
```

Альтернативный способ запуска без Makefile:

```bash
uv sync
uv run project
```

Также доступна команда `uv run database` — оба сценария запускают одно приложение.

## Команды приложения

### Управление таблицами

| Команда | Описание |
|---|---|
| `create_table <имя> <столбец:тип> ...` | Создать таблицу |
| `list_tables` | Показать список таблиц |
| `drop_table <имя>` | Удалить таблицу с подтверждением |
| `info <имя>` | Показать структуру таблицы и количество записей |
| `help` | Показать справку |
| `exit` | Выйти из программы |

Поддерживаемые типы столбцов: `int`, `str`, `bool`. При создании таблицы автоматически добавляется служебный столбец `ID:int`. Объявлять или изменять `ID` вручную нельзя.

Пример создания таблицы:

```text
create_table users name:str age:int is_active:bool
```

### Работа с записями (CRUD)

| Операция | Пример команды |
|---|---|
| Добавление (INSERT) | `insert into users values ("Sergei", 28, true)` |
| Просмотр всех записей (SELECT) | `select from users` |
| Просмотр по условию (SELECT) | `select from users where age = 28` |
| Изменение (UPDATE) | `update users set age = 29 where name = "Sergei"` |
| Удаление (DELETE) | `delete from users where ID = 1` |

Результаты `SELECT` отображаются в таблице с помощью `PrettyTable`. Условия `WHERE` используют сравнение одного столбца со значением через `=`. Операции `UPDATE` и `DELETE` применяются ко всем записям, удовлетворяющим условию.

При добавлении записи автоматически назначается `ID`, уникальный среди существующих записей таблицы. Значения должны соответствовать числу столбцов и их типам. Строки указываются в кавычках, целые числа — без кавычек, логические значения — как `true` или `false` (регистр логических значений не важен). В строковых значениях допускаются пробелы и запятые.

Например:

```text
insert into users values ("Ivanov, Ivan", 40, TRUE)
select from users where name = "Ivanov, Ivan"
```

Команды `drop_table` и `delete` требуют подтверждения: `y` выполняет операцию, другой ответ отменяет её. При некорректном вводе приложение сообщает об ошибке и продолжает работу.

## Хранение данных

Метаданные таблиц сохраняются в `db_meta.json`, а записи каждой таблицы — в отдельном JSON-файле каталога `data/`:

```text
db_meta.json
data/
    users.json
```

При следующем запуске приложение загружает ранее сохранённые таблицы и записи. При удалении таблицы удаляются её метаданные и соответствующий файл с записями. Эти рабочие файлы исключены из Git.

## Декораторы и кеширование

- **`handle_db_errors`** перехватывает `KeyError`, `ValueError` и `FileNotFoundError`, выводя сообщения об ошибках без аварийного завершения программы.
- **`confirm_action`** запрашивает подтверждение удаления таблицы или записей.
- **`log_time`** измеряет время выполнения функций `insert` и `select` с помощью `time.monotonic()`.
- **`create_cacher()`** создаёт замыкание для кеширования результатов `SELECT` по таблице и условию `WHERE`.

Повторная выборка с теми же параметрами может возвращаться из кеша без повторного выполнения `select`. После успешных `insert`, `update`, `delete` и `drop_table` кеш пересоздаётся, чтобы следующие запросы возвращали актуальные данные.

Пример сообщения о времени выполнения:

```text
Функция select выполнилась за 0.000 секунд.
```

## Проверка качества и сборка

Проверка кода с помощью Ruff:

```bash
make lint
```

Эквивалентная команда:

```bash
uv run ruff check .
```

Сборка исходного архива и wheel-пакета:

```bash
uv build
```

Проверка метаданных собранных пакетов:

```bash
uvx twine check dist/*
```

Сборка создаёт файлы в каталоге `dist/`, который исключён из Git. Проверка через `twine check` не публикует пакет.
